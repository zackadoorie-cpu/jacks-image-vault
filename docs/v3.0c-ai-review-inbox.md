# Phase 3.0C first slice: persistent AI proposal inbox and human review handoff

The owner confirmed real local Gemini inference in v3.0.2. Drive inspector is still read-only. Stable Manifest rows are checked with the existing read-only Sheet helper before and after inference. A private account/Sheet-bound proposal inbox keeps up to 100 records (500 KB) containing Drive ID/version, row, model, timestamp, exact current Manifest values and local review baseline, filename, description, tags and category. No API keys, OAuth tokens, image bytes or cloud writes are stored or performed by the queue. Corrupt storage fails closed; duplicate inspections are blocked before paid inference. Delete/export are explicit. Local image tests stay separate. Filename stem is shortened to fit the existing 96-character total limit; extension remains original.

Open in human review editor rechecks exact Drive identity/version, current Manifest D/M/N/T values and local note before prefilling selected description/tags as UNSAVED edits. User visually inspects and explicitly saves or marks reviewed using existing review editor; Sheet Approvals provides existing 10-record batch, temporary grant, separate confirmations, verified readback and undo. This first slice does not add AI-specific version checks to the later generic Sheet approval, nor automatically mark review status, stage a Sheet write, rename files or update Manifest R. Filename and category are editable local proposals only. Subsequent 3.0C work: provenance-aware filename staging and end-to-end version rechecks at write boundary; avoid claiming AI proposals are Manifest R evidence. No automatic writes or bulk AI processing.

Tests use synthetic records, wrong workspace, duplicate/full/corrupt storage, invalid names/formula targets, version/row/note drift, no direct write path and normal gallery regression CI. No paid API or personal files used in CI.
