# Jack's Image Vault v2.2 Phase 2 — Gallery Polish

Versioned as v2.2.1. The separate verified publisher repeats browser, Windows and updater-security testing before signing off the GitHub release assets.

## Changes
- A compact active-filter row appears only when a search, file type, collection,
  or nondefault sort is applied. Clicking a chip removes only that dimension,
  and Clear all resets all four. Search terms and folder names are inserted
  as text nodes, never HTML. All current saved-search, review, virtual
  collection, gallery and density controls are retained.
- Visible image cards distinguish waiting, queued, loading, ready and
  unavailable previews. Only actual loading cards animate, and
  prefers-reduced-motion disables the animation. Video poster failures
  explicitly say to open the media and play, not that video playback failed.
  Full diagnostic error details remain accessible via the placeholder title
  and media details. The existing retry workflow remains.
- A compact playback status in the media detail pane reports connecting,
  ready, buffering, seeking, playing, paused, finished and errors. Statuses
  originate from native HTMLMediaElement events with active-item guards.
  GIFs and unsupported media preserve existing manual playback/Drive actions.

## Non-goals and safeguards
- No changes to Google OAuth scopes, file names or data, Manifest/Index
  metadata, Sheet formulas, sync logic, or rename/undo permissions.
- No new automatic original downloads. Thumbnail queue stays at a maximum
  eight requests, poster decoding remains one at a time, and original
  auto-poster fetch limits remain 5 MiB. Video source, byte-range streaming
  and bounded legacy Blob fallback are unchanged.
- No new persistent private caches, CDN dependencies, or telemetry.

## Verification
- Real Chromium test uses fabricated Google data and a small decodable WebM
  to check both native stream and Blob fallback, video state events,
  5-MiB cap, working preview retries, safe filter chips, and zero writes.
- Existing Chromium 10,000-file virtualization, narrow-screen, density,
  search/serialization and UI checks remain required.
- Full Linux/Go security/stress and Windows WebView2/DPAPI/upgrade smoke
  must pass before merging.
- A separate v2.2.1 release build repeats independent validation, packages
  EXE, UI patch, desktop bundle, and verifies SHA-256 checksums.
