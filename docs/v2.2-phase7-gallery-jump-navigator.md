# Phase 7: Gallery Jump Navigator (v2.2.6, retired)

> Historical release notes only. This experiment was removed completely from
> the application in v2.2.7 after user feedback. The navigator is not available
> in any view, and these instructions do not apply to current versions.

Baseline: published and verified v2.2.5. Goal: navigate a large filtered
gallery without manually stepping through hundreds of "Load more" batches.

- A compact, accessible Jump Navigator appears only when a gallery has more
  than 96 matched files. It has a bounded range slider with a committed
  change event, a numeric "Result #" jump, and First/Middle/Last shortcuts.
  This is a logical file index in the currently active filters and sort.
- In Turbo Gallery, jumping extends `renderedCount` only as logical
  availability, scrolls to the requested row, and lets existing virtual tile
  rendering mount only a handful of overscanned rows. It does not fetch or
  decode the entire skipped result set.
- Medium (non-virtual) galleries use normal tile rendering and scroll to
  the requested result. Small galleries stay uncluttered.
- Large scrolling updates the approximate current position, and invalid
  numeric jumps are rejected without changing view or filter state.
- All actions are session-only read-only navigation. No new scopes, Drive
  writes, Sheet writes, background downloads, media playback or new storage
  formats. No change to local reviews, album membership or file metadata.

Validation: Chromium E2E with a synthetic 10,000-file index tests middle/end/
first/slider, invalid input and bounded mounted tile counts, followed by
existing deep scroll/filter/cache/media tests. Separate Windows native/
encrypted sign-in and Go security/updater/media stress checks remain mandatory.
