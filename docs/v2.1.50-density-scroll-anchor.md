# v2.1.50 candidate — gallery density scroll anchoring

## Problem

The five-step Large → Comfortable → Compact → Ultra Compact → Micro slider
changes the number of columns and fixed virtual row heights. In a long
collection, simply retaining the same `scrollY` can replace the files
underneath the user with unrelated files mid-browse.

## Change

- On the first slider input within an animation frame, remember the first
  visible gallery item's immutable file ID, logical index, and viewport top.
- Render once for the latest slider value. For Turbo Gallery, calculate the
  new column count, map the same logical item to its new row, and scroll to
  that row before re-rendering the bounded DOM window.
- Adjust the final offset from the actual returned tile position. A small,
  non-virtual gallery uses its real DOM tile directly.
- Preserve existing local preference names, focusable slider and tile actions.
- If no gallery tile is visible (or the list view is open), resizing behaves
  as before. No background downloads, Drive writes, Sheet writes or extra
  Google permissions.

## Regression coverage

The synthetic Chromium 10,000-media test now scrolls deep into the gallery,
records a visible file and its position, switches Comfortable → Micro →
Comfortable, and verifies the same file stays mounted close to the original
viewport position with bounded DOM counts. Existing mobile and viewport-first
preview checks remain unchanged.

## Shipping gate

This is not yet a released patch. Run the repository's Linux/Go, browser
Chromium and Windows/WebView2 checks on the PR before merging. Release from
the approved workflow only after checks pass. The feature is web UI only, so
existing compatible Windows launchers should not need native-server changes.
