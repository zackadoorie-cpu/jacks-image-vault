# v2.2.9 — Phase 9: Faster Gallery Search

The existing gallery's search and advanced folder picker are unchanged
visually. The goal is to stop unnecessary work when typing with 1,000+
Drive items and preserve the corrected Micro tile layout.

- **Search typing.** The current text is recorded in state on each input.
  Actual gallery matching, sorting, virtual-window update and preview rebinding
  are scheduled after 125 ms without further typing. A new keystroke replaces
  the previous timer rather than queueing extra searches.
- **Fast completion.** Clearing a query, pressing Enter or completing an
  IME composition commits immediately. Mid-composition input never triggers
  partial matching; repeated final text events cannot double-commit.
- **Safe view changes.** Any direct gallery render (new filter, saved search,
  navigation, collection change) consumes the latest state and cancels a stale
  pending search. Leaving the gallery cannot trigger a late hidden repaint.
- **Folder picker.** Filtering the *names* of folders now updates only the
  picker options and matched-count label, preserving a currently selected
  folder even if it no longer matches the typed text. The gallery is
  recalculated only when a folder is actually selected.
- **Strict preservation.** No change to gallery markup, CSS, all five density
  options, compact action layout, Turbo Gallery, album formats, playback,
  browser sign-in continuity, original file fetching or remote writes.

Browser E2E: rapidly dispatch multiple input events in one turn and verify
one render, verify IME composition isolation, Enter and Escape completion,
query chip safety, folder picker DOM identity, no hidden Drive/Sheet writes,
and a synthetic 10,000-file gallery search burst. Existing Windows
WebView2/updater, media stress, security and recovery CI remains mandatory.
