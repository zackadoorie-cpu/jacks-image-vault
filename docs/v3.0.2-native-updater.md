# v3.0.2 — native-aware update center (first safe upgrade slice)
The Gallery UI version and native Windows engine version are separate. UI patches are still supported and never replace the launcher. The official repository release check identifies a newer native version independently of the currently installed UI; if an old launcher lacks native metadata, use the official release page. Gemini refuses key operations on an engine below 3.0.1 and shows both versions.

On Windows the explicit staging action accepts only a newer official release tag, checks the exact latest release again, requires GitHub-listed bounded executable size and SHA-256, exact official URL and native confirmation, validates bytes and AMD64 PE header, then uses existing versioned launcher copy logic to keep older executables and refuse a conflicting existing file. No execution, shutdown, arbitrary repository/path, shortcut modification or credential handling in this action. A missing digest, API fallback, corrupted payload or download failure fails closed. Users of the desktop host should download the full matched bundle. Once staged, close all windows and launch the exact shown path; refresh shortcuts via existing Windows setup. Native rollback remains manual: stop all windows, run previous retained EXE with --repair if newer UI remains selected, then launch it and optionally refresh shortcuts. This does not reverse library edits. Automatic coordinated host restart and transactional shortcut switching are deferred; the desktop host owns its child process and has separate profile behavior. No claim of one-click native activation.

Test gates: exact asset URLs and digest validation, PE bytes, independent version compare, route guard, Windows safe/idempotent staging and no overwrite, old launcher fallback and existing gallery/OAuth/patch regression suites.
